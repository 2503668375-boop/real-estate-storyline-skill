# 长任务断点续作与原子交付

## 目标

让70—120页方案、长周期调研和多文件交付在任务中断、窗口切换或上下文压缩后可从最近一致状态恢复，不丢失已完成工作，不重复制造互相冲突的版本。

## 一、正式目录优先

开始前依次检查：

1. 用户指定的正式交付目录存在且可写；
2. 正式目录不是临时任务镜像、下载目录或仅供参考的只读目录；
3. 项目固定使用一个绝对路径；
4. 运行清单、底稿和成品都写入该项目目录；
5. 用户明确要求暂存当前工作区时，仍在运行清单记录未来正式迁移目标。

未完成路径检查，不得开始长篇生成。不得仅凭工具返回的“file change”声称文件长期存在。

## 二、先建运行清单

使用 `scripts/项目检查点.py init` 建立 `项目运行清单.json`。至少分为：

`条件检查 → 资料与研究 → 市场/客群 → 产品战略 → 设计任务 → 经营价格 → 定位概念 → 页面预算 → HTML/PPT分批生成 → 运行与视觉验收 → 最终交付`

每个阶段只能处于 `pending / in_progress / completed / blocked`。同一时刻最多一个 `in_progress`。

## 三、完成边界

一个阶段完成时按此顺序：

1. 把阶段产物写入确定路径；
2. 检查文件存在、非空、可解析/可打开；
3. 对产物计算SHA-256；
4. 再把阶段标记为 `completed`；
5. 记录下一阶段和恢复说明。

不得先在聊天中宣布完成，再补文件。不得把“模型已经构思”视为阶段产物。

## 四、长HTML/PPT生成

- 页面预算先完整保存，但页面正文按8—12页一批生成；
- 每批直接更新正式成品或确定的中间源文件；
- 每批后检查DOM/PPT实际页数、标签闭合、关键标记和文件可打开；
- 检查通过后登记批次范围、页数和校验值；
- 下一批开始前重新读取运行清单和成品末尾，不依赖记忆续写；
- 禁止一次性在一个超长补丁或一次模型输出中生成70—120页。

批次保存不是要求用户逐批确认。只在需要授权、重大方向选择或真实外部阻塞时暂停。

## 五、恢复协议

任务开始或恢复时：

1. 读取 `项目运行清单.json`；
2. 运行 `scripts/项目检查点.py verify`；
3. 若已完成产物校验值不一致，标记异常并先对账；
4. 找到第一个未完成阶段；
5. 读取该阶段的上游产物和恢复说明；
6. 从该阶段继续，不重做已校验阶段。

聊天记录只用于理解用户意图；文件与运行清单才是进度真相。

## 六、原子写入

运行清单使用同目录临时文件写入并原子替换。正式成品如不能原子更新，先写带 `.tmp` 的同目录文件，验证后替换。不要在外部盘断连、空间不足或权限未知时继续生成。

## 七、最终交付

只有同时满足以下条件才可声称完成：

- 运行清单全部阶段完成；
- 所有已登记产物存在且校验一致；
- 最终HTML/PPT/PDF可打开，实际页数和预期一致；
- 文件位于用户指定的正式目录；
- 最终交付验收通过；
- 返回的本地链接指向实际存在的绝对路径。

若只完成部分，明确说“已保存至第X阶段/第Y页，可恢复”，不得说“完整完成”。
