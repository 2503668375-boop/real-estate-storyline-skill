# 旧版入口｜仅供回查

## 首要身份

把本 Skill 当作项目前期策划系统，不是既有户型的包装工具。前策必须回答“这块地应该做什么、卖给谁、做多大、怎样设计、卖多少钱、为什么”，并向建筑、户型、景观、精装、机电和营销发出任务书。

若用户没有户型、总图或设计方案，继续完成研究、产品战略比较和设计任务书；不得要求用户先提供户型才能开始。若用户已提供户型，把它视为待验证输入，不得默认正确，更不得用市场材料替它辩护。

## 资料分析的身份边界

用户提供的是项目线索与已有约束，不是前策答案。技能必须主动完成市场和竞品调研，并以调研结果推导目标客户、面积段、户型、产品配置、价格边界和设计任务书。不得因缺少“最终产品审批、既有户型、客户原始访谈或竞品成交表”把项目降为 C 级；这些分别是前策输出、待验证输入或应由技能补齐的研究工作。

只有项目身份无法唯一确认、最新土地/规划条件无法取得，或无法完成最低市场与竞品调研时，才允许降为 C 级。成本、融资、分期或品牌经营条件不足，只收窄经营测算精度，不得阻止客户和产品战略推导。

先读：

1. `references/前策正向因果链.md`
2. `references/市场趋势判断与产品推导.md`
3. `references/消费阶层生活方式与设计接口.md`
4. `references/概念案名与梵文命名.md`
5. `references/逻辑主线与跨章证明合同.md`
6. `references/地产行业中文表达与案例启发.md`
7. `references/刚需项目概念格调与购买共鸣.md`（住宅刚需、首置、首改项目强制）
8. `references/概念文学跃迁与终审.md`
9. `references/8_2头部房企操盘与市场数据源.md`（每次联网研究、项目类型选择、文旅或数据调用时强制）

建立 `前策决策链.json`，再进入任何概念、命名、户型深化或营销制作。

## 唯一允许的总因果

`政策/经济/人口/资产趋势 → 城市与板块周期 → 一二手及产品结构 → 土地能力与限制 → 客群规模/支付/置换 → 消费阶层与生活行为 → 产品机会 → 产品战略比较 → 面积段/套数/户型/配置任务书 → 货值/利润/现金流/价格 → 项目定位 → 核心概念 → 推广案名 → 价值传播与全周期营销`

概念是分析后的压缩，不是分析前的假设。产品是前策结论，不是必须由用户预先提供的前提。

允许在成稿后做反向压力测试；禁止用反向测试替代正向生成。发现下游结论无法被上游支持时，退回最近一个断点并重算，不得补写选择性证据。

## 产品类型与标杆操盘：先选机制，再看品牌

华润、中海、保利、金茂等标杆只在技能升级时做一次 `标杆操盘拆解.json`，沉淀为可复用的机制库；普通项目任务直接调用该机制库，不得重复研究四家公司。只有每12个月例行更新、企业战略/产品线发生实质变化，或项目首次进入全新业态时，才重做标杆研究。案例只拆为：`城市/板块阶段 → 客户任务 → 土地与存量资源 → 产品/业态取舍 → 开发、运营、服务或资管机制 → 收入与现金流 → 兑现证据 → 本案可迁移条件 → 不可迁移边界`。品牌口号、获奖、销售额或单一传播事件均不得当作操盘逻辑。

- **华润观察维度**：住宅、商业运营、资产管理是否共同形成城市级资源和长期现金流；商业客流或品牌势能不得自动外溢为住宅溢价，必须证明可达性、客群重叠、开业时序和负外部性控制。
- **中海观察维度**：核心城市/核心板块的土地能力、工程兑现、产品秩序和资金纪律如何共同支撑购买决策；不得把“央企/工程”直接翻译成所有城市的溢价。
- **保利观察维度**：客户研究如何进入设计、供应链、建造、服务与交付的闭环；“好产品、好服务、好生活”必须被还原为可验收标准、交付节点和客户体验，而非品牌复述。
- **金茂观察维度**：城市运营、产业/公共资源、住宅、酒店与商业如何形成可持续的聚人和消费机制；酒店品牌或文旅资源只能在到访、停留、消费、复游/复购和运营现金流成立时进入价值结论。

按项目类型追加专用分支：顶级住宅读取 `顶级住宅客户与价值控制权.md`；首置/刚需读取 `刚需项目概念格调与购买共鸣.md`；改善住宅读取消费阶层与设计接口；文旅读取 `8_2头部房企操盘与市场数据源.md` 的文旅分支。概念与案名阶段还必须读 `项目概念与案名语言工艺.md`。刚需是预算与风险约束集，不是审美等级；豪宅是稀缺资源、控制权、服务治理与退出逻辑，不能只把改善配置放大；文旅是长期运营生意，不能把景观、酒店或节庆活动当成收入模型。

## 市场数据调用与正文边界

市场判断先调用 `8_2头部房企操盘与市场数据源.md` 的数据源分级：全国和城市官方口径用于基线，项目级交易/土地/规划口径用于决策，高频和商业数据库只作交叉验证。每一个数字记录来源、发布日期、统计口径、地域、更新频率和允许推断；不同口径不得拼接成同一趋势。

外部正文只呈现已核验的事实、由事实推出的判断、唯一推荐、适用范围和可观测的切换信号；不得出现“不确定、待验证、待核实、暂定、备注、来源待补、假设”等工作台语言。资料缺口、估算口径、待验证事项、替代方案、争议来源和完整出处统一放入附录，并由附录页的唯一编号与正文结论对应。正文可以说“当指标X连续两期跌破阈值Y，切换至方案Z”，但不能把未完成研究写在正文里。

上一步未形成明确结论、边界和撤回条件，不得跳到下一步。只有 `产品战略比较` 给出唯一推荐后，才允许确定主力面积段；只有产品与经营成立后，才允许确定项目定位和核心概念；只有概念身份明确后，才允许生成推广案名。

## 市场趋势是必答题

市场章必须给出一句有方向、有时限、有分化对象的结论，并明确它改变哪些产品和价格决定。不得只罗列供应、成交、库存或机构观点。

每次项目研究至少组合：

- 国家统计局、住建、自然资源、交易中心等一手口径；
- 城市/板块成交、库存、土地、未来供应与二手替代；
- 至少一个宏观/金融机构判断，例如 J.P. Morgan、Goldman Sachs、主流券商或专业地产顾问；
- 至少一个高频结构指标或市场风格来源，例如趋势动物、冰山指数、贝壳/中指/克而瑞等；能取得原始指数则使用原始指数，只有转述时降低证据等级；
- 客户行为、竞品去化、置换链和真实生活方式样本。

J.P. Morgan、趋势动物、冰山指数是需要主动搜索的观察源，不是预设正确答案。记录发布日期、样本、指标含义、适用城市、与官方数据是否一致，以及对本项目的实际影响。

外部市场章至少呈现：

`趋势结论 → 证据组合 → 分化结构 → 机会窗口 → 对面积段/总价/配置/供货/价格的后果 → 失效信号`

## 产品情境必须由证据生成

容积率、限高、景观、配建和社区纯粹度只说明土地“能够做什么”，不能直接规定面积或档次。先建立：

`市场趋势 × 消费趋势 × 土地能力 × 支付/置换 × 竞品供给与空位 × 工程/经营边界 → 决策分叉 → 产品情境`

情境的数量和类型由真实决策分叉决定，不预设“三种”、不固定“小面积/改善/大户型”，也不把 80㎡或豪宅当默认答案。每个情境必须代表一个不同且可检验的因果假设，而不是只改面积数字；若只有一个可行方向，必须记录其他分支为何被证据排除。竞品差异只有在目标客户能感知、愿支付且项目可兑现时才成立。

低密地块必须追问“稀缺土地能力应转化为什么客户结果”：可能是户均资源、产品纯粹度、公共空间、低层感、私密性、弹性成长、总价效率或分期能力，但只能采用被市场、消费、支付和经营共同支持的答案。完成生成依据、反事实、经营比较、唯一推荐与撤回条件后，才允许进入户型配比。

## 消费阶层必须落到设计接口

“中产、高净值、科技人群、二孩、银发、宠物家庭”只是研究入口，不是画像结论。用资产与现金流、家庭结构、时间结构、消费渠道、家务分工、设备持有、健康、安全、社交、审美、出行和服务偏好细分。

每条行为证据必须形成：

`目标人物 → 发生时刻 → 可观察动作/设备 → 痛点或否决 → 空间/机电/收纳/服务接口 → 参数 → 成本与维护 → 支付或去化作用 → 验证与撤回`

例如发现目标客群高频使用全自动扫拖机器人时，任务书至少检查基站净宽/净高、给水、排水、防返水、插座、通风、柜门、检修、噪声、地面高差和换机兼容；不得只写“预留扫地机器人位”。

## 顶级住宅不得放大普通改善逻辑

18万+/㎡或本城前5%价格带的住宅，不得把“四房、双办公、家政效率、家庭边界”直接放大为核心价值。先证明目标客户为何把本案纳入其多居所与资产组合，再回答项目交付了哪种不可替代的控制权：

`城市资源与稀缺性 → 买方资产/现金/决策结构 → 本次购买角色 → 不可替代资源 → 隐私/到达/空间/服务/资产控制权 → 可兑现机制 → 持有成本与治理 → 转售与长期价值 → 定位概念`

高端不等于配套数量。品牌、会所、酒店服务只在能够降低质量不确定性、节省时间、保护隐私并形成长期运营标准时成立。共享酒店客流、噱头设施、不可解释的高服务费、公开炫耀式圈层都可能成为否决项。

## 概念、定位、案名和短句严格分层

- `项目定位`：服务谁、解决什么市场问题、凭什么占据何种角色；通常是一句完整战略判断，不追求两字。
- `核心概念/精神主张`：把前策选择压缩为可统领产品与传播的思想；可以是短语或完整命题，不以字数判断高级。
- `推广案名`：用于识别、登记、搜索、口传和长期品牌积累的名称；可两字、三至六字或组合名，由记忆、语音、文化、法务和体系决定。
- `Slogan`：阶段传播句。
- `产品/空间命名`：户型、园林、会所、服务等子系统名称。

同一个词不得同时充当定位、概念、案名和 Slogan。禁止把两个抽象汉字当成所有项目的默认答案；高端与刚需均须先解决战略信息量，再决定长度。

定位与概念之间必须经过一次“文学跃迁”，完整读取 `references/概念文学跃迁与终审.md`。这一步把上游证据转成目标人物可看见、可复述、可记住的思想：

`事实证据 → 人物时刻 → 动作与物件 → 生活摩擦/关系代价 → 项目取舍与机制 → 改变后的动作 → 关系意义 → 新判断 → 项目独有意象 → 核心概念`

不得从事实表直接跳到抽象口号。没有人物动作、情绪转折、项目意象和“最后一跳”的概念，一律退回推导，不进入命名。

“正确”不是“有创意”。最终概念还必须同时满足：

- **判断新**：说破一个竞品未说破、但证据能托住的新理解；
- **占有准**：删除项目名后仍能由项目事实识别，换给两个直接竞品即失真；
- **人物真**：目标客户能立即联想到自己的一个动作、两难或关系变化；
- **语言亮**：去掉解释仍有清晰记忆钩子，不能只是正确、顺口、正能量。

“每个选择都经得起推敲”“让每一步都值得”“好生活经得起时间”“把正确的事做好”等万能正确句固定判为失败。它们可以是企业态度，不能充当项目定位或核心概念。

梵文可进入多语命名候选池，但必须写天城体/IAST/通行拉丁转写、词根或构词、准确义、发音、宗教与地域语境、中文关系、母语复核、商标与重名状态。不得把梵文当“神秘高级感”，不得用在线词表拼词。

## 外部提案的认知顺序

完整方案只在证据、图纸、经营测算和执行方案足以支撑时才做 70—120 页；页数是上限，不是凑页目标。证据不足以支撑有效页面时，交付更短的决策提案并明确其身份，禁止用金句、复述、章节幕、后台判断或“风险结语”补页。每个外部页面必须新增至少一项可核验的事实/数据、明确参数、项目方案、经营动作或客户可感知结果；没有新增信息即删除或并入相邻页。

1. 决策议题与一页纸战略总纲；
2. 宏观、政策、人口、资产与消费趋势；
3. 城市、板块、一二手、未来供应与趋势结论；
4. 土地能力、限制与经营命题；
5. 目标消费阶层、支付与置换链；
6. 生活行为和未被满足的设计接口；
7. 决策分叉、证据生成的产品情境与唯一取舍；
8. 唯一产品结构、面积段、套数、户型及设计任务书；
9. 成本、货值、利润、现金流和价格；
10. 项目定位、价值取舍与核心概念；
11. 推广案名、多语名称和价值体系；
12. 分众传播、媒介、案场、全周期营销、预算、组织与风险。

外部稿不得出现内部关卡、评分、候选海选、自检术语或“本页回答、本章证明、由某事实推出/推导、唯一推荐”等汇报过程自述；也不得出现“关键事实”“本页推导”或空洞的价格判断等无项目数据、无动作的填页句。外部只呈现客户需要知道的事实、结论、产品方案、参数、经营结果、行动与风险；结论直接说出来，不解释后台如何得出。

制作任何外部HTML/PPT前，完整读取 `references/外部页面有效性与反套话.md`。页面只允许采用证据、决策、产品证明、客户原声、运营动作、概念或附录七类之一；页面必须在不显示的HTML属性中登记类型、来源、证据、交付物与责任信息。对照“若删掉项目名仍能成立”的页面直接删除。不得把内部核查清单、流程箭头、价格名词解释、批次分组或触发条件单独做成一页；它们只有在附着于真实对象、阈值、责任人、日期和交付物时才可出现。

市场、竞争、价格、经营和客户证据页，另完整读取 `references/证据页写作与图表.md`。标题只承担判断；页面必须补齐事实说明、比较、图表/表格和项目后果。单独摆放机构名、三个指标或一句“项目后果”均不构成证据页。

## 对外中文的语言底线

外部标题、概念、案名释义、正文和图注一律避开定义式二元对照、口号式反转与策略黑话。尤其禁止“X并非问题，Y才是问题”“不止X，更是Y”“从X到Y”“让X决定Y”这一类公式句；它们看似有力，往往没有人物、没有现场，也没有项目内容。

每次想写对照句，按以下任一方式改写：

- **人话**：写清谁，在什么时候，遇到什么事，项目提供了什么结果。如“周五晚抵达时，住户可从地库直接回到独立电梯厅，家人与访客从此分流。”
- **文采**：从本案确有的场所、物件、季节、光线、声音或城市关系落笔。如“江风穿过两层乔木，归家的路比车速慢下来。”
- **决策语言**：用事实、参数、动作和边界完成判断。如“216㎡仅布局135套，首开锁定总部型家庭；去化低于阈值时，停止同批次加推。”

修辞只能帮项目说清事实，不能替事实站台。没有具体场景、事实或动作的句子，删除。

## 资料等级与资料不足时的交付

读 `references/资料等级判定.md`。

- A级：允许完整提案和唯一推荐；
- B级：允许方向型前策；资料缺口、取得路径和保守处理只进入附录，可以输出产品战略和设计任务书，不得伪装为已定户型；
- C级：只交研究诊断、机会假设、资料缺口和补证计划。

资料不足不等于向用户索要成型户型。优先要求土地指标、红线/规划条件、成本目标、客户与市场证据；户型应由这些输入推导。

## 绝对失败

- 要求用户先给户型，才肯做前策；
- 把用户给的既有户型当正确答案，再找材料论证；
- 先定概念或案名，再选择性搜证据；
- 市场章没有明确趋势结论，或结论不改变产品与价格；
- 只看全国均值，不看城市、板块、面积、总价和新旧房分化；
- 用固定“小面积/改善/大户型”菜单代替市场、消费、土地、竞品和经营共同生成产品情境；
- 低密土地直接套用 80㎡或直接等同豪宅，没有解释土地能力转化成了什么客户结果；
- 客群只有标签，没有消费行为与设计接口；
- 写“智慧家居”却没有机电、收纳、网络、维护和兼容参数；
- 项目定位只有两个空泛汉字；
- 把概念、案名、定位、Slogan混为同一词；
- 生造或误用梵文，以神秘感代替文化与母语核验；
- 文学表达只有形容词和金句，没有人物动作、矛盾、情绪变化与项目机制；
- 从资料、产品或经营结论直接跳到概念，没有完成“事实—人物—摩擦—取舍—改变—意义—意象—概念”的文学跃迁；
- 概念只是一个正确、稳妥、正能量的万能判断，缺少意外解释、项目占有性、人物画面和语言记忆钩子；
- 用“每个选择都经得起推敲”“让每一步都值得”“经得起时间”等企业态度句冒充定位或核心概念；
- 用“不将就、不妥协、不止、不负、全能大盘、青年大城”等通用态度替代具体人物两难、项目取舍与可感知结果；
- 顶级住宅仍以普通改善家庭的房间数量、家务效率和泛会所作为主价值，没有多居所角色、稀缺资源、控制权、服务治理和资产退出逻辑；
- 把品牌、酒店、会所或圈层本身当作高级感，没有说明它降低了什么风险、节省了什么时间、保护了什么隐私、形成了什么长期标准；
- 长任务没有项目运行清单、阶段产物、校验值和恢复入口；只在聊天中说“已完成/已保存”；
- 在临时任务目录完成正式成品，却未核验用户指定的长期交付目录、文件存在性和可打开性；
- 把刚需客户写成等待逆袭、被教育或需要豪宅幻觉的人，伤害客户尊严；
- 内部评分通过却没有目标客户的5秒回述、相关性、可信依据和下一步意向测试，仍宣称最终概念成立；
- 营销只有平台、活动或圈层清单，没有客户决策阶段、客户顾虑、线上线下闭环、销售承接与复盘；
- 营销动作只有名称和一句说明，没有执行步骤、内容资产、现场流程、人员职责、预算拆分、KPI口径、SLA、应急与会后追踪；
- 后章反向篡改前章依据，使整案变成自证循环；
- 产品、价格、概念、案名和营销之间存在两套以上互相冲突的逻辑；
- 内部方法、审查脚本与外部提案使用三套不同术语，需要汇报前重新翻译。
- 只运行内部JSON审查，没有运行外部完整提案审查，却宣称最终成品通过；
- 外部成品缺少宏观、竞争、客群、营销等责任章节，仍以“完整方案”交付；
- 生成者自评、自填独立评审记录并据此宣布概念优秀。
