## 一、四次中断根因（必须避开）

### 根因 1：HTML 用 `str.replace()` 替换开标签 → 45页内容双份

**症状**：所有页面内容都被复制一份，审查 `内容实质` 通过但页内重复不在检测范围；直到甲方肉眼核对才发现 P42/P43 显示同一份内容。

**根因**：`re.sub`/`.replace()` 匹配开标签后，新字符串里又包含完整页面内容；遇到相邻多页开标签完全相同（market 页、delivery 页），replace 把整页内容塞进所有匹配位置。

**纪律**：
- **HTML 内任何替换，必须按位置替换**（用 `re.sub` 带计数器，或 `re.split` 按章节切分）
- **禁用 `.replace(开标签, ...)` 这种模式**
- **每次 HTML 改动后必须跑页间相似度扫描**（SequenceMatcher > 0.6 视为异常）

```python
# 错误示范
t = t.replace('<section class="slide" data-section="market">', '<section ...>' + full_page_content)
# 正确示范
count = [0]
def repl(m):
    count[0] += 1
    n = count[0]
    return page_map[n]  # 按位置取内容
t = re.sub(r'<section class="slide[^"]*"(?:\s+data-[^=]+="[^"]*")*>', repl, t)
```

### 根因 2：审查字段合规多轮循环（每次生成底稿都要跑 3-5 轮才过）

**症状**：底稿生成后跑审查脚本，看报错列表，逐条修，再跑，再修。原因：审查脚本要求每个字段有最小长度（≥8 字 / ≥20 字）、枚举值精确匹配、字段类型是 list 而不是 str、必填字段数 ≥ N（推导链 ≥ 16、推导页面 ≥ 12、六联单 ≥ 3、章节情绪卡 ≥ 5）。

**纪律**：
- **首次生成底稿时，按 `references/统一规则.json` 的枚举与字段模板一次性合规生成**
- 每个字符串字段最少填到长度下限（用真实内容，不要 fallback 占位符）
- 每个 list 字段填到数量下限（推导链 16、推导页面 12、价值矛盾地图 3）
- 跑审查脚本时**记录失败项**到本项目验收记录，未来直接对照模板填

**字段长度速查**（来自审查脚本实际报错）：

### 根因 3：页面事实清单与 HTML 不同步

**症状**：HTML 改了 6 页内容，清单还是旧的——内容实质审查脚本检测清单"事实"字段不在页面正文里。

**纪律**：
- **每次 HTML 改动后立即用审查脚本的 Deck 类重建清单**（不是用普通 BeautifulSoup，要复刻审查脚本的 main 提取规则——h1/in_title/skip 标签都跳过）
- **重建脚本必须用审查脚本的 Deck 类**（`from 审查内容实质 import Deck`），否则字段提取口径不一致
- **清单"事实"字段必须是 list**（审查脚本要 list 类型）

```python
# 正确：从审查 Deck 视角重建清单
spec = importlib.util.spec_from_file_location('scsz', 'scripts/审查内容实质.py')
mod = importlib.util.module_from_spec(spec); spec.loader.exec_module(mod)
Deck = mod.Deck
p = Deck(); p.feed(open(html_path, encoding='utf-8').read())
# 用 page['main']、page['head'] 提取，保证100%匹配审查判断
```

### 根因 4：截图脚本走键盘事件翻页失败

**症状**：用 `page.keyboard.press('ArrowRight')` 翻页，playwright 键盘事件未传到目标页，导致 45 张截图全是首页。

**纪律**：
- **截图脚本必须让 HTML 暴露 `window.__show(n)` 与 `window.__total` 精确翻页函数**（不依赖键盘事件）
- **每次翻页后等 ≥ 800ms** 让动效稳定再截图
- **截图脚本最后必须做 md5 唯一性检查**（45 张内容全不同才放行）
- **每张图必须做文本溢出检测**（`el.scrollWidth > el.clientWidth + 4` 即溢出，定位到具体元素）

```javascript
// HTML 内暴露：
window.__total = slides.length;
window.__show = function(n) { show(n); };  // show() 函数内要用一致的循环变量名（教训：曾因 sl/s 笔误导致 show() 抛异常 45 页全截图失败）

// Node 截图脚本：
await page.evaluate((n) => window.__show(n), i);
await page.waitForTimeout(850);
```

## 二、HTML 大文件操作纪律

- **单文件 HTML > 100KB / 页数 > 30 时，分章节写入或先小验证再全量**——单次 200KB+ 的 Write 工具调用容易中断
- **改 HTML 前先 `cp` 备份**（`备份_修改前.html`），便于回滚
- **HTML 内的 `<section>` 开标签**必须含 `data-section="..."`——这是审查脚本与 Deck 解析的唯一标识
- **每个 section 必须含 `<h1>` 标题**（≥6 字，审查脚本会查）——封面与定位页通常用 `<div>` 大字，必须改成 `<h1>`
- **每个 section 的 `<div class="src">` 必须含项目锚点文字**（如"天宸·正 佳园二期"），否则审查脚本报"锚点缺失"

## 三、概念/定位变更全链同步清单

**改任何一个核心概念词**（如「定锚」→「心安处」），必须同步：

1. HTML（全局精确替换，不动专业词如"价格锚点"）
2. 8 个 JSON 底稿（市场/研究/前策/概念/顶级住宅/全周期营销/经营价格/创意终审）
3. 一页纸战略总纲
4. 页面事实清单（重建）
5. 市场数据包（如果新增证据）
6. 截图（重跑，页数不变也重跑确保内容对齐）
7. 运行清单 sha256

**禁用模式**：改了概念只改 HTML，JSON 底稿还是旧的——下次跑审查会从旧底稿里抓出"概念名"等关键字段不一致。

## 四、首次跑新项目的最短路径

1. **读**：`方法论总纲.md`（流程）+ `项目输入清单.md`（填空）+ `references/A级方案工作流纪律与中断教训.md`（本文件）
2. **生成**所有底稿时用审查脚本的字段要求一次性填齐（参照本文件第二节字段长度表）
3. **写 HTML 时**按章节分段写（封面+决策+定位 / 市场+土地 / 客户+概念+产品 / 服务+营销+经营 / 交付+附录+结尾），每段 ≤ 30KB
4. **改 HTML 时**按位置替换 + 重建清单 + 跑相似度扫描
5. **跑审查**时一次性提交所有底稿，记录失败项到本项目验收记录
6. **交付前**：截图 md5 唯一 + 全文相似度<0.6 + 内容实质 + 运行清单 sha256 + 13 道审查关卡
