# 发布会级视觉导演与版式系统

## 目的

视觉不是内容完成后的美化。它要帮助听众看见主线、证据、人物和决策。每个项目先生成自己的视觉母体，再制作 PPT/HTML；禁止默认套用黑金豪宅、满页卡片或同一模板换文字。

## 先建立视觉策略底稿

建立 `视觉策略底稿.json`：

- `项目定位`
- `核心概念`
- `视觉母体`
- `母体事实来源`
- `几何语法`
- `版面网格`
- `主色与语义`
- `字体层级`
- `图像策略`
- `图表语法`
- `动效语法`
- `页面原型`
- `章节节奏`
- `禁止项`
- `关键页验收`

视觉母体必须能回到土地、建筑、城市结构、人物动作、地方材料或核心机制。例如河网、山脊、轴线、院落、工业构件、光影、潮汐、街巷尺度。不能只写“高级、国际、艺术、科技”。

## 从定位生成设计语法

使用以下链条：

`定位/概念 → 可指认事实 → 视觉母体 → 几何与留白 → 色彩与材质 → 页面原型 → 动效 → 现场观看效果`

视觉母体至少改变五项：

- 网格或构图；
- 章节幕的转场方式；
- 图表或机制图的造型；
- 图片裁切与留白；
- 页码、导航或进度系统；
- 动效方向与节奏；
- 关键概念页的空间感。

若换一个项目仍无需调整，视觉系统不合格。

## 版面底线

现场横屏演示可采用16:9舞台；手机阅读可采用响应重排或另做阅读版，按用户观看场景选择并实际验证。统一设计系统，不将固定画布强加到所有交付。

- 使用 12 栏或可解释的模块网格；
- 左右安全区建议 96—128px，上下安全区建议 64—88px；
- 标题、正文、图注、页码统一对齐线；
- 每页只有一个视觉重心；
- 标题承担结论，不使用栏目名占据主标题；
- 现场版正文通常不小于 20px，图注不小于 16px；
- 字体层级最多四级；
- 主色不超过三种，白、黑、灰中性色可作为明度系统；预警、涨跌等语义色只在必要处使用；
- 正文字量以观看距离、信息任务与阅读节奏决定；高密度查数和低密度主张分别设计，不按统一字数拆页；
- 表格只用于精确查数，主稿优先用排序、尺度、位置和趋势图解。

## 页面原型库

以下页面原型按内容选择，以信息完整、阅读节奏与审美统一为准，不设最低原型数量：

1. `hero`：封面、章节高潮、唯一推荐；
2. `evidence`：大数据、来源、口径与结论；
3. `map`：城市、板块、竞品与空间关系；
4. `human`：人物动作、一天、家庭决策链；
5. `mechanism`：事实如何变成结果；
6. `comparison`：旧答案与本项目选择；
7. `product`：总图、户型、剖面、参数与场景；
8. `economics`：成本瀑布、货值、现金流、敏感性；
9. `timeline`：传播、首开、持销、交付；
10. `decision`：推荐、风险、批准与切换信号。

HTML可用 `data-prototype` 与 `data-visual-role` 辅助组织；重复或转场按信息及观看节奏判断，不机械按页数切换。

## 视觉角色

每页只承担一个主要视觉角色：

- `orient`：告诉听众现在在哪里；
- `prove`：呈现证据；
- `explain`：解释机制；
- `compare`：完成取舍；
- `feel`：让人物处境可感；
- `decide`：要求批准；
- `act`：说明执行。

图片、图表、文字层级必须围绕这个角色组织。装饰图不算视觉证据。

## 图片与证据

- 优先项目实景、航拍、规划、图纸、样板、材料、人物真实动作；
- 无项目图时使用标明身份的示意图，不伪装实景；
- 图片底板设置稳定留白或暗层，标题不压建筑主体；
- 同一图片不跨多页重复充数；
- 版权、来源、拍摄时间和示意状态进入底稿或注脚；
- 不以奢侈品、酒杯、跑车、模特肖像替代目标客户证据。

## 数据与机制图

- 数字页必须显示时间、范围、单位和来源；
- 市场、竞品、价格页的图表数据必须来自 `市场数据包.json`；自绘曲线、箭头或抽象节点只能解释机制，不能证明成交、库存、去化或客户支付；
- 图表标题直接写结论；
- 颜色只编码一项含义；
- 对比使用共同基准；
- 机制图不超过七个主节点；
- 价值推导优先使用“事实—机制—人物—结果—支付”的连续图解；
- 营销执行优先使用“阶段—客户顾虑—动作—目的—KPI—切换”的阶段营销总表；
- 复杂明细进入附件，不把主稿做成 Excel 截图。

## 动效

动效只用于：

- 建立先后顺序；
- 揭示因果；
- 强调变化；
- 完成章节转场。

每个页面最多一种主动效。使用 300—700ms 的克制过渡；支持 `prefers-reduced-motion`；禁止无意义漂浮、循环呼吸、炫技 3D 和影响阅读的粒子背景。

## 发布会节奏

把 70—120 页视为一场现场演讲：

- 开篇 3—5 页快速建立问题与唯一结论；
- 每章先定问题，再给证据，最后做选择；
- 数据密集页后安排低密度结论页或人物页；
- 在关键证据、取舍和概念出现处形成叙事重点，位置按论证决定；
- 核心概念只出现一次正式发布，前文逐步集中，后文持续证明；
- 价格、风险和执行页恢复克制，不强行诗化；
- 结尾回到开篇主线，给批准事项和下一步。

## HTML/PPT 技术规范

- HTML 使用 UTF-8、`lang=zh-CN`、静态 DOM、离线可运行；
- 用户要求离线时，将字体、脚本、图片和运行依赖本地化并验证断网可用；
- 支持键盘、触摸、页码、全屏、减弱动画；
- 页数从 DOM 实际集合计算；
- PPT 保持文字、图表和关键形状可编辑；
- PPT/HTML/PDF 同源于一页纸、主线底稿和页面预算表；
- 页面写 `data-section`、`data-proof-node`、`data-prototype`、`data-visual-role`；
- 逐页渲染，截图数必须等于实际页数。

## 视觉验收

先看缩略图总览，再看 100% 单页。

缩略图检查：

- 是否一眼能看出章节与高潮；
- 是否连续多页同构；
- 是否整套都是卡片；
- 是否出现局部过密或大片空洞；
- 是否主色失控；
- 是否图片风格互相打架。

关键页逐一检查：

- 封面；
- 一页纸；
- 市场证据；
- 人物代价；
- 价值推导；
- 核心概念发布；
- 产品/户型；
- 价格与现金流；
- 全周期营销战役；
- 需批准事项；
- 结尾。

每页回答：

1. 3 秒能否读出结论；
2. 视觉是否提供信息，而非装饰；
3. 标题、正文、图注是否在统一网格；
4. 是否存在溢出、遮挡、低清、乱码；
5. 是否能在会议室后排阅读；
6. 删除一个元素后是否更清楚；
7. 是否体现本项目而非通用豪宅模板。

## 硬失败

- 默认黑金、满页卡片、奢侈品图库；
- 每页三个以上视觉重心；
- 连续四页以上同一构图；
- 章节幕只写章节名，没有承上启下；
- 用字体变小容纳超量内容；
- 外网资源导致断网失效；
- 图片与数字无来源；
- 核心概念页很华丽，产品和执行页仍无机制；
- 自动审查通过但未逐页渲染。
- 用同一张装饰性示意图替代市场、竞品、产品、价格等不同页面的证据。
